# Карточки услуг, преимуществ и информации

Пять оформлений используют общий `ui/card-action/CardAction.astro`. Карточка
отвечает за вид, одноимённый компонент во множественном числе — за список и
раскладку. `CardAction` выбирает действие и HTML-семантику; существующий
`js/modules/modals.js` открывает и закрывает окно.

| Новый компонент | Назначение | Совместимый прежний импорт |
| --- | --- | --- |
| `CompactFeatureCard`, `CompactFeatureCards` | Компактная плашка с иконкой | `Services` (список с загрузкой services.json) |
| `IconFeatureCard`, `IconFeatureCards` | Круглая иконка или изображение, подпись снизу | `ServicesAltItem`, `ServicesAlt` |
| `ImageFeatureCard`, `ImageFeatureCards` | Круглое фото, цветная плашка и пояснение | `SpecialServicesItem`, `SpecialServices` |
| `BenefitCard`, `BenefitCards` | Иконка, заголовок и HTML-описание | `AdvantagesItem`, `AdvantagesList` |
| `InfoCard`, `InfoCards` | Подпись и иконка с оформлением от композиции | `InfoItem`, `InfoList` |

Старые файлы являются тонкими адаптерами, стили в них не дублируются. Старые
названия типов экспортируются как совместимые aliases. Это позволяет обновлять
шаблон независимо от контента сайтов. Сложные страницы HAVAL и другие
потребители используют общий механизм уже через адаптеры.

## Данные действия

В `item.action` задаётся один из четырёх вариантов:

```ts
{ type: 'none' }
{ type: 'popup', id: 'common-modal', title: 'Записаться', formName: 'Запись на сервис' }
{ type: 'link', url: '/service/' }
{ type: 'new-tab', url: 'https://example.com/' }
```

`none` выводит `div` без ссылки и исключает прежний `url`. `link` оставляет
переход в текущем окне, даже для внешнего URL. `new-tab` использует `_blank`
и добавляет `noopener noreferrer`, сохраняя остальные значения `rel`.

Popup получает `role="button"`, `aria-haspopup="dialog"`, `aria-controls` и
активацию пробелом; Enter работает нативно. Корень остаётся ссылкой, чтобы
содержимое всей карточки (заголовки и блоки описания) сохраняло допустимую
HTML-структуру и контракт существующего контроллера `.popup-link`.

В popup доступны `title`, `subtitle`, `formName`, `comment`,
`chooseDepartment`, `filtering`, `sorting`, `dealerName`. Они переводятся в
существующие `data-*` атрибуты контроллера. Если следующий триггер не передал
имя формы или комментарий, возвращаются исходные значения окна. Переданные вызывающим кодом
`data-title`, `data-form_name` и остальные метаданные имеют приоритет.

Для старых данных поддерживаются `url`, `target`, `rel`. Только отдельный
фрагмент `#common-modal` или `#common-modal-*` распознаётся как прежний popup.
`#details` и `https://example.com/#common-modal` остаются обычными ссылками.
Пустой URL, `#` и прежний `javascript:void(0)` становятся статичным блоком.
Явный `action` всегда приоритетнее старых полей. Для нового кода задавайте его
явно; произвольный popup ID поддерживается через `action.type="popup"`.

Сервисные адаптеры сохраняют имя формы `Запись на сервис. {title}`. Адаптеры
`SpecialServices` дополнительно сохраняют popup по умолчанию, как в прежней
реализации. Сам `ImageFeatureCard` без действия статичен.

## Проверка и выкладка

`node --test src/ui/card-action/resolveCardAction.test.mjs` проверяет контракт
действия и сервисные адаптеры. В guide есть отдельные страницы всех карточек,
списков и `CardAction`; четыре режима показаны рядом. Фокус демонстрационного
окна управляется локальной оболочкой guide, формы и внешние переходы отключены.

Сначала публикуется и распространяется совместимый шаблон, затем данные
guide с импортами новых имён. Контент дилеров менять для включения общей
логики не требуется.
