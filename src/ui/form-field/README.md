# FormField

Общая обёртка Input и Textarea: необязательная подпись, подсказка и сообщение
ошибки. Нативные элементы и их атрибуты остаются в отдельных компонентах.

- `classes` и нативные атрибуты относятся к control; `wrapperClass` — к обёртке.
- `classes` дополняет базовое оформление. Нативный `class` заменяет его целиком;
  явный `title` имеет приоритет над HTML-подсказкой из errorText.
- `label` и `hint` добавляются явно. Без них существующая форма не меняет вид.
- Явный `id` сохраняется; при подписи, подсказке или required генерируется
  уникальный ID. `aria-describedby` объединяет подсказку с существующим значением;
  ошибка связывается отдельно через `aria-errormessage` и `aria-invalid`.
  Скрытый текст ошибки не попадает в обычное описание поля.
- Control и `.error-message.<name>` остаются непосредственными детьми одной
  обёртки. Показом ошибки управляет CSS-класс `hidden`.
- Прежние errorClasses и отступы Input/Textarea сохранены.
- Datalist принадлежит Input. Семантика value/children Textarea не изменена.
- Цвета и фокус наследуются из существующих стилей и переменных бренда.
- Нативный `form.reset()` очищает ошибки, `aria-invalid` и custom validity только
  у полей сбрасываемой формы; отменённый reset не меняет это состояние.

```astro
<Input name="phone" type="tel" label="Телефон" hint="Номер для обратного звонка"
	placeholder="+7 999 123-45-67" required errorText="Укажите телефон" />
```

При прямом использовании FormField передайте `controlId` и тот же `id`
нативному элементу внутри default-slot. Слот `after` используется для datalist.

Минимальная совместимая зависимость — `@alexsab-ru/scripts@0.21.1`.
Порядок выпуска: SDK, затем распространение FormField. Обработчик зависимости
должен искать `.error-message` в обёртке и допускать отсутствие ошибки, а не
полагаться на `nextSibling.nextElementSibling`.
