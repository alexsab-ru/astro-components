# Редактирование astro-json в dev

`pnpm ddolcdln` синхронизирует данные локально, включает `linkJson` и запускает Astro. Для уже подготовленного сайта: `pnpm linkJson`, затем `pnpm dev` (или `pnpm dev_local`).

Источник выбирается один раз: `DOMAIN` из окружения или `.env`, каталог из `--local-path`, затем `ASTRO_JSON_LOCAL_PATH`, затем `../astro-json`. Комментарии и кавычки в `.env` обрабатывает dotenv. Например: `pnpm linkJson --local-path /path/to/astro-json`. Один игнорируемый symlink `src/scss/.json-site` сохраняет этот выбор для Vite и Tailwind; `setBrand` занимается только темой.

Живое редактирование охватывает `banners.json`, `pages/index.astro` текущего сайта и коллекцию `special-offers`. Остальные данные, страницы и компоненты обновляются обычной синхронизацией.

- Баннеры подключаются symlink, главная — локальной Astro-обёрткой. Внешние классы Tailwind сканируются через `@source`.
- Акции остаются обычными локальными файлами. Dev-плагин отслеживает изменения, добавление, переименование и удаление в исходных папках; собирает common → brands → site с теми же правилами `from`/`only`, что обычная синхронизация. При удалении дилерской версии восстанавливается версия нижнего слоя, если она существует.
- Изменяются только файлы, содержимое которых изменилось. При добавлении, удалении или переименовании MDX dev-сервер автоматически перезапускается для обновления карты импортов Astro 5. Обычные правки существующих файлов обходятся без перезапуска.
- Настройки брендов и правила берутся из исходного `settings.json` и синхронизированного `src/data/site/pages.json`. После смены DOMAIN, брендов, реестра или каталога данных остановите dev и повторите локальную синхронизацию и `linkJson`.

`pnpm linkJson --detach` превращает ссылки и обёртку в локальные копии и выключает подключение (после этого перезапустите dev). `downloadCommonRepo` делает это автоматически перед синхронизацией, чтобы генераторы не записали результат через symlink в исходный репозиторий.

Не коммитьте сгенерированную обёртку `src/pages/index.astro` в общий шаблон. Перед сборкой CI используется обычная синхронизация; dev-плагин при build не запускает watcher.

Проверки: `pnpm test:local-json`, `pnpm test:layer-resolution`, `pnpm build`.
