# astro-components: общий шаблон дилерских сайтов

Один шаблон Astro/React/Alpine/Tailwind собирает разные сайты из `astro-json`. Этот файл общий для `astro-components` и производных `astro-brand-*`, `astro-dealer-*`, `astro-main-*`: распространяется вместе с шаблоном через merge, а не отдельными копиями. Общие исправления делай в `astro-components`; изменения конкретного форка не распространяй автоматически.

Перед работой проверь Git-корень, текущую ветку, незакоммиченные изменения и активный домен. Если репозиторий находится в workspace `astro-main`, дополнительно прочитай его родительский `AGENTS.md`. В отдельном клоне или worktree сначала найди реальный workspace; `../AGENTS.md` и `../astro-json` не гарантированы.

## Где менять

- `src/blocks/` — секции; `src/ui/` — атомарные элементы; `src/page-builder/` — рендеринг блоков из данных.
- `src/site-shell/` — общие header/footer/modals; `src/templates/`, `src/layouts/`, `src/pages/` — шаблоны и маршруты.
- `src/react/`, `src/js/` — клиентская логика; `src/integrations/` — SEO/schema и сборка.
- `src/data/`, часть `src/content/`, `src/pages/` и overrides синхронизируются из `astro-json`. Для режима `--local` проверь ожидаемый скриптом путь к локальному клону (обычно `../astro-json`); в другом расположении не предполагай, что он существует. Найти источник до правки. `src/scss/brand.css` генерируется, вручную не менять.

## Обычные действия

Команды сверены с `package.json` 2026-11-13; запускать здесь после проверки активного `DOMAIN` (не печатать `.env` целиком).

| Цель | Команда |
|---|---|
| Разработка с локальными данными | `pnpm ddol` |
| Проверка с локальными данными, завершается | `pnpm verify` |
| Данные уже актуальны, нужна только сборка | `pnpm build` |
| Локальный dev без обновления данных | `pnpm dev` |
| Разработка с ценами/плейсхолдерами | `pnpm ddl` |
| Такая же завершающаяся проверка | `pnpm verifyl` |
| Нужен свежий склад | `pnpm ddlcars` / `pnpm verifycars` |
| Изменились меню, маршруты или ссылки | `pnpm test_links_local` после сборки |

`ddol`, `ddolcd`, `verify`, `verifycd` сейчас используют `--local -cd`: очищают и заново синхронизируют генерируемые данные. Сначала проверить их локальные изменения. `dd*` — постоянный сервер, не проверка с кодом завершения. Сетевые фиды/цены запускать только когда нужны задаче, с достаточным таймаутом.

## Что читать дальше

- В workspace `astro-main`: `docs/agent-frontend.md` — выбор слоя, сайта, бренда, подготовка данных и фидов; `docs/agent-workflows.md` — стиль, проверки и rollout. Это внешние справочники workspace, не обязательные файлы каждого форка. Если workspace отсутствует, сверяй команды и структуру по текущему репозиторию; не запускай rollout по догадке.
- `package.json` — точный текущий состав команд; `.prettierrc` — форматирование. Новую секцию регистрировать в BlockRenderer и задавать через данные.

Не запускать `pnpm start` поверх существующей конфигурации: он копирует `.env.example` в `.env`. `pull_without_merge` содержит reset/rebase и не относится к безопасным повседневным командам.
